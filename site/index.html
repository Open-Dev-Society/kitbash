A repository with 17× fewer stars took the lead slot, because it fit better. That inversion is the entire product.

Sheet 02 — why now

Your agent will happily rewrite a PDF parser.
It shouldn't.

Search has always ranked by popularity rather than fit, so the right small library stays buried. That's the old problem. The new one is sharper: when a model will write anything in twenty minutes, rebuilding feels free — so nobody looks first.

That instinct is fine for glue and CRUD. It is quietly dangerous for problems whose correctness was won over years of edge cases that appear in no specification — PDF parsing, container muxing, timezone math, OAuth, Unicode normalization, rate limiting under contention. A rewrite of those looks right and is subtly wrong, and you find out in production.

The thing being sold is not speed

Four components you never build beats four components you build quickly. Kitbash deletes scope rather than accelerating it — which is a different axis from every other tool pointed at this problem.

Sheet 03 — the three calls

Every part gets a verdict

This is the judgment a senior developer makes in ten seconds and no tool has externalized. A tool that recommends a repository for everything is a tool nobody believes — so saying "write it yourself" is a required outcome, not a failure state.

Borrow

Take the dependency

A maintained library exists and the correctness here was hard-won. Rewriting it is the mistake.

Kitbash

Read it, adapt it

A good reference exists but isn't a clean fit. Take the approach, leave the dependency.

Write

No repository needed

Generic enough that your agent should just write it. A component you never take on is one you never maintain.

Sheet 05 — how it's built

There is no model inside the server

Recall is the product — knowing that a 144-star parser exists at all. So the recall happens in the largest model available, the one already running your session, rather than a smaller one we could afford to host. The server's job is to stop it lying.

Tool 01

kitbash

Hands the agent a decomposition rubric and an output contract. Returns nothing that could pass as a finished answer — because if it could, the verification step would get skipped.

Tool 02

kitbash_verify

Fact-checks every asserted repository against the GitHub API, scores health from real commit activity, drops anything that 404s, and renders the report. The agent chains it itself.

Ranking puts the agent's own ordering first, with repository health able only to demote. Sorting by stars would have silently re-buried the exact repository the rubric just dug up — which is how a tool ends up contradicting its own premise.

Sheet 06 — assembly

Two lines to install

Runs inside Claude Code, Claude Desktop, Cursor, or any MCP-compatible agent. It reads your existing gh credentials, so there's no key to configure and nothing to sign up for.

$ npm install && npm run build $ claude mcp add kitbash -- node ./build/index.js

Then describe something you were about to build, and see how much of it you don't have to.
